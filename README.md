デザインシミュレーター Pro — 開発者向け説明書
このファイルは、`design\_simulator.html`(単一HTMLファイル)の仕組みと、コードを修正する際に
知っておくべきポイントをまとめたものです。
---
1. 全体の仕組み
2Dエディタ: Fabric.js(キャンバスライブラリ)で、丸(またはSVGで読み込んだ形)の上に
写真・テキスト・スタンプ・手描き図形を配置する。
3Dプレビュー: Three.js。2Dエディタの内容を切り出して画像化し、立体の板(押し出しジオメトリ)に
テクスチャとして貼り付ける。
テンプレート: 「輪郭(仕上がり線・カットライン)」「塗り足し線」「ストラップ穴」の3つの情報を
持つ `template` というオブジェクト1つが、2Dガイド線・3D形状・書き出しデータすべての元になっている。
丸もSVGから読み込んだ形も、すべて同じ仕組みで扱われる。
2. フォルダの規約(HTMLファイルと同じ場所に作る)
すべて「連番のファイル名を置くだけで自動的に一覧に出る」方式(サーバーのフォルダ一覧機能に
依存しない、ブラウザ側で1つずつ試して存在確認する仕組み)。
フォルダ	ファイル名の付け方	用途
`stamp/`	`stamp1.png`, `stamp2.png`, …	スタンプ機能の選択肢(PNG、透過推奨)
`template/`	`template1.svg`, `template2.svg`, …	一般公開用の「テンプレート選択」の選択肢
`background/`	`background.jpg`(または`.png`)	ページ全体の背景(1枚を画面いっぱいに表示)
`background/`	`pattern.png`	上記が無い場合のみ使われる、繰り返し模様の背景ロゴ
スタンプ・テンプレートは存在チェックに上限(現在40個・20個)がある。40個(20個)を超えて
追加した場合は、コード内の `STAMP\_MAX\_CHECK` / `TEMPLATE\_MAX\_CHECK` の数字を増やす。
SVGテンプレートには、塗り足し線(赤系の線 or id="bleed") と
仕上がり線(青系の線 or id="finish") の2つの`<path>`が必要。判定できない場合は
「面積が大きい方を塗り足し線」とみなす。
3. 管理者モード / 一般公開モード
Ctrl+D で切り替え(`document.body`に`admin-mode`クラスが付く/外れる)。
CSSの `.admin-only` / `.public-only` で表示・非表示を切り替えている。
管理者用: 「SVGテンプレート読込」(ファイルを直接選んで読み込む、`handleSVGTemplateUpload`)
一般公開用: 「テンプレート選択」の帯(`template`フォルダの一覧、`loadTemplateGallery`)
4. 表面／裏面(両面デザイン)
`currentSide`('front'か'back')で今どちらを編集中かを管理。
画像・テキストなどの「ユーザーが置いたもの」だけを`frontObjectsData` / `backObjectsData`に
JSON形式で保存し、切り替え時に`fabric.util.enlivenObjects`で復元している
(`switchSide`関数)。塗り足し線・カットライン・穴などの「テンプレート自体」は両面共通。
ベースカラーも両面共通(側面の色として3D側で常に反映)。
5. 3Dプレビューの仕組み(重要・要注意ポイント)
表面・裏面それぞれの2Dキャンバスを画像化し、`ExtrudeGeometry`(押し出し形状)に貼り付けている。
表と裏は完全に別のMeshオブジェクト(`frontCapMesh` / `backCapMesh`)にしている。
以前、Three.jsが自動で割り振る「面ごとのマテリアル番号」を当てにして表裏を判定していたが、
形状や穴の有無で番号の並びが変わってしまい、表裏を取り違えるバグが繰り返し発生したため、
この方式に変更した。表裏の色・テクスチャを変える処理を触る場合は、必ず
`plateMesh.userData.frontCapMesh` / `backCapMesh` を直接使うこと(マテリアル配列の
インデックスを当てにしない)。
裏面は物理的に「ひっくり返して見る」ことになるため、テクスチャを貼る直前に左右反転させている
(`update3DTexture`内)。2Dエディタや書き出しデータ自体は反転させていない。
ストラップ穴は、丸テンプレートのみ自動生成(`template.hole`)。カスタムSVGテンプレートでは
穴は付けない(形状に合わないため)。
Retina(高解像度)ディスプレイ対策で、キャンバスを切り出す際に`canvas.getRetinaScaling()`を
掛けている。ここを削ると、Retina環境で「一部だけ切り出されて拡大表示される」バグが再発する。
6. SVG書き出し(`exportLayeredSVG`)
`fabric.Canvas.toSVG()`の出力を、以下の4レイヤーに仕分けし直している。
テンプレート(塗り足し線・カットライン・穴)
添付画像(写真・スタンプ)
手描き(描画ツールで作った図形・ペン)
テキスト
レイヤーでまとめる都合上、書き出したSVGでは重なり順が「テンプレート→画像→手描き→テキスト」に
統一される。エディタ上で画像とテキストの前後関係を個別に調整していても、SVG上ではこの順序に
変わる。
裏面もデザインされていれば、表面用・裏面用の2つのファイルを書き出す(`hasBackContent`で判定)。
7. ローカルでテストする際の注意(ブラウザのセキュリティ制限)
HTMLファイルを**ダブルクリックして直接開く(`file://`のアドレス)**と、以下が正しく動かないことがある。
スタンプ・写真を3Dテクスチャ化する処理(`canvas.toDataURL()`)がブロックされ、その面が
真っ黒になる。
`fetch()`を使う処理は`file://`では完全に使えない(このアプリでは`fetch`は使っておらず、
代わりに`<object>`タグや`<img>`タグの読み込みで代用している箇所がある)。
確実にテストするには、簡易ローカルサーバーを使うこと。
```
cd (このHTMLファイルがあるフォルダ)
python -m http.server 8000
```
その後ブラウザで `http://localhost:8000/design\_simulator.html` を開く。実際のサーバー
(例: daiomfg.co.jp)に設置した場合は、これらの制限は発生しない。
8. fabric.js / three.js が読み込めなかった場合
CDN(cdnjs.cloudflare.com、jsdelivr.net)からのライブラリ読み込みが、広告ブロッカーや
セキュリティソフト、社内ネットワークの制限などでブロックされることがある。その場合、
スクリプトの実行がその時点で止まり、「画面が少し暗くなるが何も選べない」という分かりにくい
壊れ方をする(ポップアップの背景幕を表示する処理は先に定義されているため動くが、それ以降の
変数がすべて未初期化のまま残るため)。
この状態になった場合、画面上部に赤いエラーバナーが表示されるようにしてある
(`typeof fabric === 'undefined'`のチェック)。バナーが出た場合は、ネット接続や拡張機能の
設定を確認してもらう。

10. 既知の制限事項
カスタムSVGテンプレートの3D表現では、表と裏で別デザインを貼れるが、丸テンプレートと違い
「側面(押し出しの壁)」の質感は表裏共通。
テンプレート選択・スタンプの一覧は、番号が連続している前提(`stamp1`, `stamp2`…)。
番号が欠けている(例: stamp1, stamp3のみでstamp2が無い)場合、そこで探索が止まるわけではなく
単にそのファイルが無いだけとして次の番号を試すので、欠番があっても問題なく動く。
